# Kare Space Program — правила проекта

KSP-подобная игра, реальная Солнечная система 1:1, реалистичная графика. **Unity 6000.6.3f1 + HDRP 17.6**, ПК.
Общие правила — `~/.claude/CLAUDE.md` (Cocos-скилы тут не применимы, это Unity).

## Документы
- `docs/GDD.md` — дизайн-документ, ссылаться на §-пункты в комментариях кода.
- `docs/SCENE_SETUP.md` — **следующий шаг**: игровой слой и сборка сцены Flight (вручную / автосборкой),
  шпаргалка по API ядра.

## MCP
MCP for Unity (CoplayDev), `.mcp.json` → `http://127.0.0.1:8767/mcp`. Car_Train занимает 8765 — порт хранится
в EditorPrefs на всю машину, поэтому `McpPortPin.cs` перезаписывает его при загрузке редактора.
Проверка: `curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8767/mcp` → 406 = сервер жив.
Если сервер жив, а сессия пишет ECONNREFUSED — переподключить через /mcp (сессия стартовала раньше редактора).

## Соглашения
- Кадр P = эклиптика J2000 (правая, z — полюс); Unity = P с SwapYZ. Нос борта = +Y.
- `Vessel.Position` — относительно центра `Body`, невращающиеся оси. `body.OrientationAt(t) * forward` = полюс.
- `Throttle <= 0` глушит двигатель; повторный запуск тратит зажигание и может требовать ullage.
- Автопилоты работают только в физике; рельсы режет `Universe.WarpLimitTime`.
- Комментарии по-русски, «почему», со ссылкой на §GDD. Числа — константами с парой-зависимостью в комментарии.

## Подтверждённые грабли
- **Рантайм-материалы HDRP не валидируются**: ключи ставить руками. `Plume.mat` терял `_EMISSIVE_COLOR_MAP` (Validate
  снимает без текстуры в ассете) → факел без градиента, «странный цвет». Решение: `new Material(plume)` + текстура +
  `EnableKeyword`. Детальная карта грунта так же: `_DETAIL_MAP` + `_UVDetailsMappingMask (0,1,0,0)` для UV1.
- **Стол поднимает ракету**: `LaunchSite.PadHeight` (6 м) учитывает `PlaceOnSurface`, иначе сопла в бетоне. Пара — `LaunchPadView`.
- **Обход треугольников Unity**: лицевая сторона (p0,p1,p2) смотрит по `Cross(p1−p0, p2−p0)`; первая версия стола была вывернута.
- **Скрин MCP `manage_camera screenshot`** пишет только внутрь проекта: `output_folder: "Temp/Shots"`.
- **В проекте не было HDRP-ассета**: `GraphicsSettings.currentRenderPipeline == null` → всё HDRP/Lit пурпурное.
  Builder создаёт `Settings/HDRP.asset` и ставит по умолчанию; первая установка — долгий реимпорт шейдеров, MCP молчит. Плюс `PlayerSettings.colorSpace = Linear` — в Gamma HDRP не рисует; и лайтмапы High Quality (внутренний `SetLightmapEncodingQualityForPlatform`, Wizard ругается).
- **`VisualEnvironment.planetCenter/planetRadius` — в километрах**, сцена в метрах (делить на 1000).
- **Тени Солнца пропадают при большой дальней плоскости** (HDRP 17.6, тень ракеты на столе): near 0,1 — far 1e6 ✓,
  3e6/1e7/2e8 ✗; near 1 — far 1e7 ✓; near 2 и 20 — far 2e8 ✗. Каст патча ни при чём. Решение: near 1 / far 1e7,
  все тела — в «оболочку» 5e6…9,5e6 (`BodyRenderer.Project`, мерило — расстояние до горизонта, чтобы
  активное тело вблизи не сжималось и совпадало с патчем). GDD §2.7 (far 2e8) этим заменён.
- **Автоэкспозиция в космосе выбеливает кадр**: гистограмма видит чёрное небо и уходит к EV −5 (белый кадр
  на 124 км). Лечится нижним пределом EV на свету (`SkyController.SunlitEvMin` = 12, плавно с высотой до 30 км).
- **Светящееся (факел) — только эмиссией.** `_UnlitColor` HDRP/Unlit мимо экспозиции: 1 нит при EV 14 уже белый.
  Эмиссия экспонируется. Ещё грабли того же кадра: `Color.white * nits` умножает альфу, а аддитив — цвет на
  альфу (alpha 50 587 → белый экран); туман на прозрачных добавляет голубое рассеяние в каждый слой
  (`_EnableFogOnTransparent` 0); `ValidateMaterial` снимает `_EMISSIVE_COLOR_MAP`, если текстура только в MPB.
  Физичные 2·10⁵ нит на аддитиве из 4 стенок + bloom = весь кадр белый; 3·10³ при EV 14 — нормальное ядро.
  **Общий `MaterialPropertyBlock` — `Clear()` перед каждым рендерером**: после отделения ступени корпус
  наследовал `_EmissiveColor` факела (22 нит) → ночью при EV −5 белый экран при выключенном Солнце (01.10.2026).
  Признак: кадр не зависит от направления камеры, при фикс. EV 12 борт серый (≈10³ нит без света).
- **Звёзды** — `Editor/StarFieldBaker.cs`: EXR 4096×2048 в нитах (0m = 2,54e-6 лк / Ω текселя), импорт
  кубмапом с `maxTextureSize = W/4` (иначе грань 2048, 24 МБ), BC6H; в PBSky `spaceEmissionTexture`, множитель 1.
- **СА-1976 — высоты геопотенциальные**: 22 632 Па на 11 км геопотенциальных, не геометрических.
- **`Vessel.RemainingStats` учитывал только работающие двигатели** → заглушенная ступень перед посадкой
  «не имела Δv», планировщик посадки ничего не мог. Теперь: взведена + топливо + (работает или есть запуски).
- **После смены SOI на рельсах пересчитывать `WarpLimitTime`** (`AdvanceRails`), иначе ускорение
  перепрыгивает момент зажигания, спланированный уже в сфере Луны.
- **Автопилот узла жёг запуски**: флаг `started` ставить в начале `Update`, иначе каждый цикл ullage
  считался новым зажиганием.
- **Парашют без рифления давал 40 g** («Восток»). Рифление: 3 % площади за 1 с, держать 4 с, раскрытие 4 с
  (`FlightPhysics.ChuteReef*`) → 8,5 g.
- **Облёт обратной стороны Луны (farside)** попадал в темноту: нужны окно старта по плоскости
  (`LaunchWindow`) + ограничение времени перелёта `maxTransfer` 2,5 сут.
- **Посадка на Луну**: минимальная тяга КТДУ (25 % от 16 кН) больше лунного веса — зависнуть нельзя.
  Схема: прогноз RK2 (шаг 0,5 с) + бисекция момента зажигания так, чтобы скорость 40 м/с наступала на
  «воротах» ≈136 м; дальше терминальный закон постоянного торможения 6 м/с², последние 3 м — свободное
  падение (касание 3,3 м/с). Зажигание на 51 км при 2485 м/с, остаток 717 кг.
- **Повреждения по умолчанию выключены** (`FlightPhysics.AeroBreakup/HeatDamage`, из `GameBootstrap` и тумблеров панели H);
  тесты ядра включают оба — автопилоты проверяются по строгим правилам. `Vessel.AngleOfAttack` — в **градусах**
  (Qα в панели H раньше умножался на Rad2Deg ещё раз). Клавиши: W — нос к +X связанных осей, S — к −X, D — к −Z, A — к +Z; на столе X — север, Z — запад
  (`PlaceOnSurface`), поэтому D = восток, как в KSP; камера на старте смотрит на север (восток справа).
- **КТДУ взводится отделением II ступени** (`Separate(1, igniteNext)`), иначе на торможении лишний шаг.

## Правка файлов (Windows, Git Bash)
- Длинный Python в heredoc Bash падает — писать скрипт в файл (скретчпад) и запускать `python файл`.
- Замены через Python: `io.open(..., newline='')`, учитывать CRLF, assert на число вхождений.
- `perl -i` на файлах с кириллицей не использовать — портит кодировку.
